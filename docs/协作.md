# 双端协作

## 第一次迁移

1. Mac 将当前两端正式源码整理并推送到私有 GitHub。
2. Windows 在新目录完整克隆该仓库，不覆盖原 Windows 工作目录。
3. Windows 从新仓库的 `windows/` 运行验证和完整 Release 构建。
4. Mac 从新仓库的 `mac/` 运行原有测试和 Release 构建。
5. 双端确认源码提交相同、功能与迁移前一致后，新仓库成为唯一权威源码；原目录再按用户授权清理。

## Git 没有保存什么

- 编译生成的 EXE、DLL、驱动包和缓存由构建脚本重新生成。
- Windows 证书、模型凭据、Agent 配置和已安装程序继续留在 Windows 本机。
- Mac 签名身份、系统权限和已安装应用继续留在 Mac 本机。
- 日志、崩溃转储和临时调试数据不进入仓库。

因此，另一台电脑拉取后不会缺少源码；第一次只需要按该平台说明完成依赖准备和完整构建。

## 日常流程

开始工作前拉取，完成后推送，另一端随后拉取。双方读取全部源码，但默认只修改自己的平台目录。协议和共同规则变更必须由另一端核对，双端实测前不宣称完整验收。
